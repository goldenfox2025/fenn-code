# Ancora 0.1.2

Resizable panes, a project menu with notification levels, @ to hand a message to a thread, threads that leave each other messages, a plan card at the top of each thread, and switching model or agent while a reply runs.

> **Unofficial.** Ancora is an independent open-source project, not affiliated with, endorsed by or sponsored by Anthropic, OpenAI, xAI or Qoder. "Claude" is a trademark of Anthropic.

**Download:** `Ancora-Setup-0.1.2.exe` (installer) or `Ancora-0.1.2-win.zip` (unzip anywhere and run `Ancora.exe`). The build is not code-signed, so if SmartScreen asks, choose **More info → Run anyway**. Releases are Windows only: macOS and Linux build from source with `build.sh` (see the README).

## What's new

- **Resizable sidebar and thread panel.** Drag the inner edge of either one (the pane follows the pointer), or focus it and use the arrow keys. Double-click or press Home for the default width. Ancora remembers the width you chose. When the window gets narrow, the sidebar keeps its width and the thread panel gives way. If even that leaves too little room, the panel opens over the conversation, and Esc or a click outside closes it.
- **Project menu like Claude's.** The 「…」 or right-click menu on a project has open with, pin (P), rename (R), notifications, settings (S), archive (A) and delete (D). There are four notification levels: every new message; the project chat and anything that needs you (the default); only what needs you; or nothing. "Needs you" means a decision, a permission request or a stuck thread.
- **@ a thread from the project chat.** Type @ (also after Chinese text, as in 「请@整理」) and pick a thread. The message goes straight to that thread, and the project chat keeps a single 「已转给 …」 line.
- **Threads can leave each other messages.** A thread can hand another its results with a note, sent now, when the other is free, or after its current task. The sender sees where the message went and whether it arrived, and can cancel it while it waits. The receiver sees who it is from and what came with it. The board shows when a message is waiting.
- **A plan card at the top of each thread.** It stays put and updates in place. Done steps have a filled check, the running step a spinner with its time, waiting rows a ⊙, and steps not yet started a dashed circle. It opens when a turn starts and folds to one line when everything is done. When the agent sends its own ACP plan, the card shows that. Waiting on your decision, or on another thread, is added by the app. Steps that only narrate the interface ("reply to the user", "send a card") are left out.
- **Quieter threads.** Each thread is one well-defined task. It works without chatting and speaks only with a result, a blocker or a decision for you. Progress goes on the plan card. The coordinator learns of finished threads from one up-to-date list, without a note in the chat.
- **Switch model or agent while a reply runs.** The menus stay open. Another model, mode or thinking level applies from the next turn, and the reply keeps going. Another agent takes over with your next message, so the reply isn't cut while you choose; if it is still running when you send, it stops then, what it said stays (marked 「已中断：换成了 …」), and the new agent is told where it stopped. Picking the first agent again cancels the switch.
- **Threads open full screen as in Claude.** The full-screen button lays the thread over the project chat, with mark-as-resolved and close in its header; Esc returns.
- **Files beside a chat, and the project Library.** The folder button in a chat's header opens a pane with the working folder as a tree (with a filter), the opened file on the right (Markdown rendered, code and text as is, images shown), and the files the agent changed marked with a dot or listed under 「改动」. In a project, the same view is the 库 tab next to 讨论串; the other views (outputs, project files, memory, routines, milestones) moved under 「…」.
- **Background.** The same pane lists the chat's sub-chats and the commands the agent runs through Ancora, with a stop button for each running command. The folder button shows a dot while something runs.
- **/ commands.** Type / in the composer for a menu as wide as the composer: Ancora's own commands first, then the agent's (such as /compact), each with an icon for its kind and its description. /子对话 hands the rest of the line to a new sub-chat (in a chat), /讨论串 starts a thread (in a project). A picked command becomes a chip in the composer (Backspace or × removes it), and it stays highlighted in the sent message.
- **A sub-chat starts with the background.** It gets the main chat's latest lines and can read more of the main chat itself when it needs to.
- **Sub-chats delete on their own.** Deleting a sub-chat removes its card from the main chat; deleting the main chat keeps its sub-chats as chats of their own.
- **A folder in one click.** A chat or project without a folder offers 「在默认文件夹里新建」 and 「选择文件夹…」 in its files pane. Without a choice, a chat still gets its folder once the agent makes files.
- **A chat keeps track of its sub-chats.** Before its next turn the main chat's agent gets one up-to-date list of its sub-chats (state, current step, latest result), only when something changed, and can look them up any time. It still can't steer them.
- **Compact on request.** When the agent offers its own compact command (Claude Code's /compact), the context ring's menu has 「压缩上下文」.
- **Retry keeps the session.** Retrying or editing your last message continues the agent's session (and its cache) instead of replaying the whole conversation.
- **Long replies stream smoothly.** Only the part being written is re-rendered.
- **Commands work without a folder.** A chat with no working folder lets the agent read, write and run commands in its own scratch folder instead of refusing. Anything outside asks first, and the prompt can make that folder (its whole project when it has a .git) the chat's working folder; what the agent already made moves in without replacing your files. Modes that let the agent work anywhere (bypassPermissions, full-access) aren't asked.
- **Quicker model picks.** The model you pick shows at once, and quick successive picks keep the last one. A chat with no session yet opens its own to switch, and the next message uses it, instead of a throwaway session. The home picker answers from the remembered list and reads the model's own options in the background. A message sent while a switch runs waits for it.
- **A queue above the composer.** Messages sent during a reply wait in a tray just above the composer, as in Codex and Claude. Each has 立即发送 (stops the reply and goes next; a model you picked meanwhile is switched first), edit (back into the composer) and delete. Stop puts them all back in the composer instead of dropping them.
- **Grok's permission mode in the menu.** Grok has no ACP mode, so its 「权限模式」 (in the model menu, under the models) is driven by its own `/always-approve on|off`: 每次询问 or 全部允许. Typing the command yourself updates the menu too.
- **Antigravity.** A new backend for Google Antigravity (agy) through Google's own ACP server, `agy_acp_server`, since the agy command line has no ACP mode. Settings → Agent backends → Antigravity can install it (downloads Google's archive from dl.google.com into ~/.agy-acp-server, with the commands shown first). Sign in with a Google account (「登录」) or a Gemini API key; a default model can be set so new sessions start on it.
- **Folder headers for the app's own folders.** A chat whose folder Ancora made gets a folder header in the sidebar like any other, with + to start another chat there.
- **Smoother motion.** One timing for everything: hover colors fade, and dialogs, panes and toasts arrive with a short fade and rise. Reduced motion turns it off.

## Fixes

- Grok's context ring now shows how full its context is, using the figure Grok itself reports (the same one its /session-info shows). Its window size comes from Grok's model list.
- A turn with nothing to report, such as a / command Grok answers itself, no longer copies the previous turn's tokens and cost. Totals that were counted twice before this fix are corrected when the app starts.
- Grok's /context draws only in Grok's own terminal. In Ancora it now runs /session-info, which shows the context in the reply.
- Grok's /goal now shows the goal, whether it is paused, and its deliverables in the plan card. Its subtasks and automatic context compaction each show as one step.
- Thinking, tool calls and folded steps in a reply now share one row height, with even spacing.
- The usage popover is redone after Claude's: the context with a bar, the cost when the agent reports one, and the last reply's time to first response and output speed. It no longer scrolls.
- The context ring is now an arc. Like the popover's bar, it turns amber as the context fills and red when it is nearly full, and moves smoothly as the figure changes.
- Codex's new input no longer shows as 0: newer codex-acp already takes the cache out of the input, and Ancora took it out again. The agent's own total now decides, so every version counts right.
- Antigravity is no longer offered an upgrade once installed (its server version ships with Ancora), and it can't sign in while it is being installed. Whether it is signed in comes from the Gemini API key or the Google sign-in it keeps, so 「已登录」 shows right after signing in.
- Stopping an agent on Windows now stops the programs it started too (Antigravity's server starts a second one, which used to stay behind and lock its files, so a reinstall failed).
- When Ancora is opened from the Start menu or a shortcut and no proxy variables are set, it passes on the system proxy, so downloads, npm and the agents reach the network as they do when started from a terminal.
- Grok shows as signed in from the grok.com sign-in it keeps (or an API key); an earlier failed check no longer shows 未登录 over the real state.
- Grok's own background commands and monitors show in the background pane with its description, state and exit code. Grok runs and stops them, so they show their state without a stop button.
- Output speed (tok/s) shows under 「最近一次回复」 in the usage popover and beside each reply's usage. Replies that call tools count too, leaving out the time the tools ran. A reply an agent hands over in one burst (Codex buffers its output) is timed from the send, rather than showing thousands of tokens per second.
- The new-chat page is laid out like a chat: the composer sits where a chat's does, and the room above holds widgets. Three come built in: the tokens used each day for the past year, as on a GitHub profile (one square a day, darker for busier days, the day's tokens and replies on hover); a few figures (the year's tokens, today's, the days with usage and the longest streak); and the most used models, each with its share. Each card's 「…」 menu moves, removes or brings back widgets, and new widgets can be added later (by plugins too). They count new input and output across every chat, and stay hidden until there is usage. Each reply now records its agent and model; earlier replies count under their chat's model.
- Compacting the context right after a restart, before the agent has connected, no longer fails; the session is resumed first.
- A / command that runs without output now says so in the reply, instead of leaving an empty reply.
- The ring's 「压缩上下文」 no longer posts a /compact message. It shows one line in the transcript: 「正在压缩上下文…」, then 「已压缩上下文」.
- A turn now reads in the order it happened. Each bout of thinking is one folded line (「思考了 6 秒」), and its reasoning renders as formatted text. Tool calls stand on their own lines, outside the thinking. Everything the agent writes shows as the reply. Long runs of tools fold into one line that says what they did. Tool titles name files by file name rather than their whole path, and web searches say what they looked up.
- Codex connects faster. Ancora runs its ACP adapter with Node directly, skipping npm's cmd.exe shim, and starts the Codex program the adapter ships with directly too. On the new-chat page, Codex starts and opens a throwaway session in the background, so the first message no longer waits for Codex to load its config, plugins and MCP servers.
- An agent's / command reaches it exactly as typed, even as the first message of a new session, before the agent has listed its commands.
- Typing Grok's /always-approve on or off is remembered, so a restart no longer brings back the other setting.
- Antigravity's card in Settings says 未安装 and offers 安装 when its server isn't there. The help text after a failed install mentions npm only for npm installs.
- Stopping a reply while the agent is still starting ends it at once.
- Failed replies no longer offer 添加回应.
- Queued messages show their actions only on hover. The tray's text lines up with the composer's, and in the glass look the tray is frosted like the composer.
- Background chores, such as naming a chat, no longer appear in Codex's own session list. Ancora removes their session afterwards when the agent supports that.
- A thread's first prompt no longer carries a hand-over section it doesn't need.
- After a restart, the coordinator gets the thread list once, with states in words.
- A 「需要您决定」 line in the project chat greys out once you've chosen.
- Starting a thread no longer raises a desktop notification for the coordinator's one-line reply.
- If you switch agents twice in quick succession, the later choice is the one that sticks.
- The model menu names the real model: a stand-in like "Default (recommended)" shows as the model it stands for, or is left out when no one can tell which model that is.
- Claude Code's thinking level no longer reads 「每次询问」. That was its "Default" level, mistranslated as a permission mode. The level now starts at Medium, and the model chip shows only the model name.
- One **default folder** (Settings → General, 文档/Ancora unless you change it) replaces 「常用文件夹」 and 「自动建的文件夹放在」. A new project gets its own subfolder there; a chat gets one once the agent makes files. Any chat or project can still use a folder you pick.
- A chat is never filed under your home folder, a drive root or Ancora's own data folder. Chats an earlier version put there move back to the plain chats.
- Switching 玻璃效果 on or off no longer shifts message bubbles by a pixel.
- Grok's diagnostics log no longer fills with 「Got response to unknown request skills-reload」: those were Grok's answers to its own internal requests, which Ancora now ignores.
- The project panel's tabs no longer squeeze into a vertical 「讨论串」 when the panel is narrow, and 「新建定时任务」 sits at the top of the routines list.
- A thread's first turn is about half as long as before (about 5,200 characters of prompt and tools, down from about 9,600). Tools for running the project (the board, routines, memory upkeep) stay with the coordinator, and computer control's tools are offered only while 电脑控制 is on.
- The folder picker opens in the chat's current folder or the default folder, not on the desktop, which Windows can be slow to list.
- Real models whose names start with "Auto" or carry "(recommended)" are listed again; the tag is left off.
- Upgrading no longer makes an old 常用文件夹 the default folder: it stays among the recent folders. A project an older version put in the home folder loses that folder.
- An agent no longer loses Ancora's notes when it compacts its context. Claude Code and Grok get them as part of their system prompt; other agents get them again at the top of the next message after a compaction, whether the agent announces it (shown as a 「压缩上下文」 step) or its reported context suddenly halves (Qoder).
- Switching 玻璃效果 no longer flashes: the page cross-fades, and the window material changes after the fade.
- Claude Code's "Agent" option reads 角色 (Agent in English), with 默认 and its own subagents such as claude-code-guide; it was mistranslated as 每次询问.
- A project an older version put in the home folder now loses that folder in its chat and threads too, so the coordinator no longer opens a session there.
- The send button stays grey for /子对话 until you write what to do; the English 后台 list says "Started just now".
- The reaction menu is one compact row of emoji instead of a tall list, and reactions show as small pills.
- A / command in a sent message is accented text instead of a chip inside the bubble, and two messages in a row leave room for the copy and edit buttons between them.
- Stop (or 立即发送) works while the agent is still connecting; the message isn't sent.
- When you refuse a request, the agent is told why ("the user did not allow…") instead of "Internal error".
- A chat keeps following the newest message after a reply is cut short or something above changes height; only your own scrolling stops it.
- A look change cut short by the next one no longer logs an error.
- Menus and buttons only offer what applies now. With a folder chosen, the folder menu is about that folder (open it, choose another, recent ones, no folder) instead of suggesting other project folders. 重试 shows only on the last reply and not while one runs, and a failed reply has one retry, not two. 转为讨论串 shows once. Copy and edit hide on messages with no text. Settings offer 登录 only to an installed backend that isn't signed in, and 设为默认 only to one that can answer. The setup guide skips sign-in for a backend that is already signed in. 压缩上下文 waits for the first turn. Searching projects no longer shows archived ones in the sidebar or the first-run invitation on the projects page, and a thread search no longer changes the 「都已解决」 line. An empty settings field can't be saved.
- Antigravity signs in again by itself in each new server process (with the Gemini API key, or the Google sign-in it stored), and gets Ancora's notes in its system prompt where it advertises it.
- Computer control no longer picks agents by whether they "see images": the list in Settings is gone and every agent gets the tools. A model that can't see the first screenshot is told by it to stop and ask you for a model that can.
- The 「后台」 pane lists only work that outlives its reply: commands still running when the reply ends, and the agent's own background tasks (Grok). Commands that finished inside a reply are steps of that reply and stay there. Click a command to read its output; while it runs, the output follows live.
- `/rename <name>` renames the conversation in Ancora too. A silent agent command still says it ran, but text that only starts with / and isn't an agent command no longer gets that line.
- The copy and edit buttons of a message sit beside its bubble, so they no longer overlap the message above.
- Menus stay attached to their button when the list behind them reorders (a busy chat moving up the sidebar).
- The usage popover's 「压缩上下文」 reads "Compact context" in English; Grok's own step is now 「自动压缩上下文」. Web searches count as 「搜索了 N 次网页」 in a fold, not as 「用了 N 个工具」.
- Every 「正在…」 state (loading models, compacting, checking, reading output) shimmers like a reply's live steps, so it reads as work under way. An agent slow to start says so after a few seconds (「正在启动 Antigravity…」, the first start can take half a minute), and the model menu stops waiting after 90 seconds with 重试 instead of loading forever.
- A scheduled task names its agent directly (the default one to start with); there is no 「默认」 choice. When its results go to a project, the agent field is hidden, since the project's chat has its own.
- A / command the agent doesn't have is no longer sent to it as an ordinary message (「/compact」 to Antigravity, which has none, made the model answer it as text): Ancora says the agent doesn't list it, and Enter again sends it as written (a path such as /tmp, or a command the agent takes without listing it). `/rename name` renames the conversation in the app when the agent has no /rename of its own. On the new-chat page there is nothing to rename yet, so it says to start the chat first instead of sending the command to the agent.
- A chat's plan card clears once its plan is finished and you write again, and when the chat moves to another agent (which never saw that plan). An agent that empties its plan removes the card.
- The usage figures drop replies that are gone (a deleted chat, a regenerated reply) without a restart. A model with a sliver of the usage reads <1%, not 0%.
- An agent still starting after 90 seconds says so in the model menu (「X 还在启动 · 重试」) instead of 「无法加载模型列表」. A Grok task that failed without an exit code reads 「失败」, not a made-up exit code. Codex usage without a total no longer shows new input as 0.
- Antigravity's leftover servers are looked for once per app start, not before every launch.
- Antigravity servers left running after a crash or a forced quit (Antigravity's server doesn't exit when Ancora goes away) are ended before its server starts and before a reinstall, so they no longer lock its files. Only copies whose parent has exited are ended.

- Approvals come one at a time, in the chat or project that asked: the oldest waits on screen with 「还有 N 个等您确认」 under it, and the next one takes its place without the card jumping or flashing.
- Output speed is shown as tok/s and the time per output token (TPOT) once a reply ends, on the reply's usage line and in the usage popover. When a reply has no speed, the popover says why: the agent reported no output tokens, the reply was too short to time, it waited on you or a tool, or it was stopped. Live speed while streaming would need estimates (ACP doesn't stream token counts), so there is none. An agent's own / command is no longer timed or counted as a reply without usage.
- 「立即发送」 in the send queue is an icon button like the others in that row.
- Qoder: a command it runs shows its output. Qoder runs commands itself and reports them as a terminal Ancora never opened, so the step read 「[terminal toolu_…]」; the output now comes from what it sends alongside (this applies to any agent that reports commands this way).
- Qoder: the context ring and automatic compaction come from Qoder's own session log (it reports neither over ACP), so the context figure is real and Ancora's notes are sent again after Qoder compacts on its own. Qoder's /compact can't run over ACP, so it has no compress button.
- Signing in to an agent outside Ancora (`qodercli login` in your own terminal) while it is running: 重试 now works. Agents that read their sign-in only when they start are restarted once when they say signed out and nothing else is running on them, and the composer's 未登录 updates.
- A reply that stops at the agent's turn limit, length limit or a refusal says so under the reply, instead of reading as finished.
- The new-chat page's widgets update when a chat is deleted while you are on it.
- No personal paths or names in the app or its tests: Ancora.exe's company and copyright read "Ancora contributors" (not Electron's default "GitHub, Inc.").

## Not yet tested on a real machine

- Whether Grok reports usage over ACP: Settings → About → Diagnostics shows it.
- Qoder signed in. The real qodercli 1.1.72 and 1.1.73 were run up to sign-in (install detection, start-up, the 未登录 state and how to sign in). Everything after sign-in (models, modes, effort, plan, commands, approvals, usage, the context from its log) was checked against a stand-in that replays the messages qodercli sends, read from its package, not against a real account. Picking a model in Qoder also changes Qoder's own default model.
- How the plan card looks when a real agent sends an ACP plan.
- The 后台 list only shows commands an agent runs through Ancora's terminal that outlive their reply, plus Grok's background tasks. Codex and Claude Code run their own shells, so their commands may not appear there.

# Ancora 0.1.2

侧栏和讨论串面板可以拖动调宽。项目菜单新增了通知分档。在主对话里可以用 @ 把消息直接交给讨论串。讨论串之间可以互相留言。每个讨论串的顶部有一张计划卡。回复进行中也能换模型或 agent。

> **非官方项目。** Ancora 是独立的开源项目，与 Anthropic、OpenAI、xAI、Qoder 均无关联，也没有得到它们的认可或赞助。「Claude」是 Anthropic 的商标。

**下载：** 安装包 `Ancora-Setup-0.1.2.exe`，或免安装的 `Ancora-0.1.2-win.zip`（解压到任意位置，运行 `Ancora.exe`）。程序没有代码签名，如果 SmartScreen 拦截，点「更多信息 → 仍要运行」。发布页只提供 Windows 版本，macOS 和 Linux 请用 `build.sh` 从源码编译（见 README）。

## 新功能

- **侧栏和讨论串面板可以调宽。**
  - 拖动面板的内侧边缘就能调宽度，宽度随鼠标实时变化；也可以选中边缘后用方向键调。
  - 双击边缘或按 Home，恢复默认宽度。
  - 调好的宽度会被记住。
  - 窗口变窄时，侧栏保持您设的宽度，讨论串面板先变窄。再窄的话，面板会改成浮在对话上方，按 Esc 或点面板外面就能关掉。
- **项目菜单和 Claude 一样。**
  - 在项目上点「…」或右键，菜单里有：打开方式、置顶 P、重命名 R、通知、设置 S、归档 A、删除 D。
  - 通知分四档：所有新消息；协调者与 @提及（默认）；仅 @提及；无。
  - 「@提及」指需要您本人处理的事，包括要您做决定、请求权限，以及讨论串卡住了。
- **在主对话里 @ 讨论串。** 打 @ 后选一个讨论串，消息会直接发给它，主对话里只留一行「已转给 …」。中文写法「请@整理」也能弹出列表。
- **讨论串之间可以留言。**
  - 一个讨论串可以把成果连同留言交给另一个讨论串。送达时机有三种：马上送、等对方空闲时送、等对方做完手头的事再送。
  - 发出方能看到留言发给了谁、送到没有，还没送到时可以取消。
  - 收到方能看到留言来自哪个讨论串，以及附带的产物。
  - 看板上会显示哪个讨论串有留言在等着送。
- **讨论串顶部有计划卡。**
  - 卡片固定在顶部，原地更新。
  - 已完成的步骤是实心勾，进行中的步骤转圈并显示用时，等待中的是 ⊙，还没开始的是虚线圈。
  - 新一轮开始时卡片自动展开，全部做完后收成一行。
  - 后端发了自己的 ACP 计划时，卡片就显示它。「等您决定」「等另一个讨论串」这类行由应用自动加上。「回复用户」「发卡片」这种只是复述界面动作的步骤会被去掉。
- **讨论串更安静。**
  - 每个讨论串只负责一件定义明确的事，安静地做。只在有结果、卡住了或需要您决定时才说话，进度都写在计划卡上。
  - 协调者从一份最新的讨论串名单里得知哪些做完了，主对话里不会多一条通知。
- **回复进行中也能换模型或 agent。**
  - 回复进行中，菜单也能打开。
  - 换模型、模式或思考档位，从下一轮开始生效，当前回复不会中断。
  - 换 agent 也不会马上打断：选好后，从您发下一条消息起才正式换。如果那时回复还没说完，才会停下，已经说的内容保留，并标上「已中断：换成了 …」，新的 agent 会知道上一轮停在哪里。发送前再选回原来的 agent，就等于取消。
- **讨论串可以像 Claude 一样全屏。** 点全屏后，讨论串铺满项目主对话的位置，顶部有「标记为已解决」和「关闭」，按 Esc 退出。
- **对话旁边能看文件，项目有了「库」。**
  - 对话标题栏右边的文件夹按钮会打开一个面板：左边是工作文件夹的目录树，可以筛选；右边预览打开的文件（Markdown 会渲染，代码和文本原样显示，图片直接显示）。
  - agent 改过的文件带一个圆点，也可以点「改动」只看这些文件。
  - 项目右侧的「库」标签是同一个视图，和「讨论串」并列。其他视图（成果、项目资料、项目记忆、定时任务、里程碑）收进了「…」菜单。
- **后台。** 同一个面板里列出这个对话的子对话，以及 agent 通过 Ancora 运行的命令。正在运行的命令可以点停止。有东西在运行时，文件夹按钮上会有一个圆点。
- **/ 命令。** 在输入框里打 /：对话里用「/子对话」把这行后面的内容交给一个新的子对话；项目里用「/讨论串」开一个讨论串；agent 自带的命令（例如 /compact）列在后面。
- **/ 命令菜单。**
  - 在输入框里打 /，弹出和输入框一样宽的菜单：先列 Ancora 自己的命令，再列 agent 自带的命令（例如 /compact）。每条有表示类别的图标和说明。
  - 选中的命令会变成输入框里的一个标签，按退格或点 × 可以去掉；发出去的消息里，这个命令也会高亮显示。
- **子对话带着背景开始。** 用 / 开子对话时，子对话会拿到主对话最近的内容，需要更多时可以自己去读主对话。
- **子对话可以单独删除。** 删掉子对话，主对话里它的卡片也会去掉；删掉主对话，它的子对话会保留，变成独立的对话。
- **一键给对话配文件夹。** 没有文件夹的对话或项目，在文件面板里可以点「在默认文件夹里新建」或「选择文件夹…」。不选也没关系：agent 做出文件时会自动建好。
- **主对话能掌握子对话的进展。** 主对话的 agent 在下一轮开始前，会收到一份最新的子对话名单（状态、当前步骤、最新结果），只在有变化时才给，也可以随时查看。它仍然不能指挥子对话。
- **手动压缩上下文。** agent 自带压缩命令时（例如 Claude Code 的 /compact），点上下文圆环，菜单里有「压缩上下文」。
- **重试沿用原来的会话。** 重试或编辑最后一条消息时，沿用 agent 原来的会话和缓存，不再把整段对话重放一遍。
- **长回复显示更流畅。** 流式输出时只重新渲染正在写的那一段。
- **没选文件夹也能运行命令。** 没有工作文件夹的对话，agent 在自己的临时文件夹里读写文件、运行命令，不再被拒绝。要动临时文件夹以外的地方时会先问您，提示里可以直接点「设为工作文件夹」，把那个文件夹（有 .git 时是整个项目）设成这个对话的工作文件夹，之前做出的文件会移进去，不会覆盖您已有的文件。agent 处在完全放行的模式（如 bypassPermissions、full-access）时不再询问。
- **换模型更快。** 点下模型立刻显示。连着点几次，以最后一次为准。还没开会话的对话，会直接打开它自己的会话来换模型，下一条消息接着用，不再另开一次性的会话。首页的模型菜单直接用记住的列表，模型自己的选项在后台读取。切换还没完成时发的消息，会等切换完成再发。
- **输入框上方的发送队列。** 回复进行中发的消息，像 Codex 和 Claude 一样排在输入框正上方。每条都可以「立即发送」（停下当前回复，接着发它；中途选了别的模型会先换好）、编辑（放回输入框）或删除。按停止后，这些消息全部退回输入框，不会丢。
- **Grok 的权限模式可以在菜单里改。** Grok 没有 ACP 的模式接口，所以它的「权限模式」（在模型菜单里，模型列表下方）用它自己的 `/always-approve on|off` 来切换：每次询问，或全部允许。您自己打这个命令，菜单也会跟着变。
- **Antigravity。** 新增 Google Antigravity（agy）后端。agy 命令行本身没有 ACP 模式，所以用的是 Google 官方的 ACP 服务 `agy_acp_server`。在 设置 → Agent 后端 → Antigravity 里可以安装（先列出命令，再从 dl.google.com 下载 Google 的压缩包，解压到 ~/.agy-acp-server）。可以用 Google 账号登录（点「登录」），也可以填 Gemini API Key；设了默认模型后，新会话直接从这个模型开始。
- **应用自己建的文件夹也有标题。** Ancora 给对话建的文件夹，在侧栏里和其他文件夹一样有标题，点 + 就能在那里开新对话。
- **动画更顺。** 所有动画用同一套节奏：悬停颜色渐变，弹窗、面板和提示出现时有短暂的淡入和位移。系统设置了「减少动画」时全部停用。

## 修复

- Grok 的上下文圆环现在会显示上下文用了多少，用的是 Grok 自己报告的数字，和它的 /session-info 一致。窗口大小取自 Grok 的模型列表。
- 没有用量可报的一轮（比如 Grok 自己处理的 / 命令）不再沿用上一轮的 token 和费用。之前被重复计入的合计，会在启动时更正。
- Grok 的 /context 只在它自己的终端里显示。在 Ancora 里改为执行 /session-info，回复里会显示上下文用量。
- Grok 的 /goal 现在会在计划卡里显示目标、是否暂停和交付进度。它启动的子任务和自动压缩上下文各显示为一个步骤。
- 回复里的思考、工具调用和折叠的步骤现在行高一致，间距均等。
- 用量弹窗参照 Claude 重做：上下文一行加进度条；agent 报告费用时显示费用；最后是最近一次回复的首个回复用时和输出速度。不再出现滚动条。
- 上下文圆环改成弧形进度，和弹窗里的进度条一样，快满时变成琥珀色，接近满时变成红色，数字变化时有过渡。
- Codex 的「新输入」不再显示为 0：新版 codex-acp 已经把缓存从输入里扣掉，Ancora 又扣了一次。现在按 agent 报告的总数判断要不要扣，各个版本都对。
- Antigravity 装好后不再提供「升级」（它的服务版本跟着 Ancora 发布），安装或升级时不能同时登录。是否已登录按 Gemini API Key 或它保存的 Google 登录来判断，登录完成后会立刻显示「已登录」。
- 停止 agent 时在 Windows 上会连同它启动的子进程一起停掉（Antigravity 的服务会再启动一个进程，以前会留下来，锁住文件导致重装失败）。
- 从开始菜单或快捷方式打开 Ancora 时，没有设置代理环境变量就会沿用系统代理，下载、npm 和 agent 都能联网，和从终端启动一样。
- Grok 按它保存的 grok.com 登录（或 API Key）显示「已登录」；之前某次探测失败留下的「未登录」不再盖过实际状态。
- Grok 在后台运行的命令和监视器会出现在后台面板里，带上它写的说明、运行状态和退出码。这些由 Grok 自己管理，所以只显示状态，不提供停止按钮。
- 输出速度（tok/s）显示在用量弹窗的「最近一次回复」里，每条回复的用量旁边也会显示。调用了工具的回复同样计算，工具运行的时间不算在内。agent 一次性交出整段回复时（Codex 会缓冲输出），从发送时开始计时，不再显示成每秒上万个 token。
- 新对话页面改成和对话一样的布局：输入框在对话里的位置，上面原本放对话的地方放小组件。自带三个：和 GitHub 个人页一样的每日用量热力图（每天一格，用得越多颜色越深，悬停显示当天的 token 数和回复数）；几个数字（过去一年的 token 数、今天的、有用量的天数和最长连续天数）；常用模型排行和各自的占比。每张卡片的「…」菜单可以移动、移除或加回小组件，之后也可以加新的小组件（插件也能加）。统计所有对话的新输入和输出，还没有用量时不显示。每条回复现在会记下用的是哪个 agent 和模型；更早的回复按所在对话的模型计算。
- 重启后还没连上 agent 时点「压缩上下文」，不再报错，会先恢复会话再压缩。
- / 命令执行后如果没有输出，回复里会写明，不再留一条空回复。
- 圆环菜单里的「压缩上下文」不再发出一条 /compact 消息，对话里只显示一行：先是「正在压缩上下文…」，完成后变为「已压缩上下文」。
- 一轮回复按发生的先后显示：每段思考折叠成一行（「思考了 6 秒」），展开后按格式显示；工具调用单独成行，不再放进思考里；agent 写的文字都作为回复显示。连续很多个工具会折叠成一行，写明做了什么。工具标题里的文件只显示文件名，不显示完整路径；网页搜索会写明搜了什么。
- Codex 连接更快：Ancora 直接用 Node 运行它的 ACP 适配器，不再经过 npm 的 cmd.exe 启动脚本；适配器自带的 Codex 程序也直接启动。在新对话页面，Codex 会先在后台启动并打开一个用完即删的会话，第一条消息不用再等它加载配置、插件和 MCP 服务。
- agent 自己的 / 命令会原样送到它那里，即使是新会话的第一条消息、agent 还没列出它有哪些命令时也一样。
- 输入 Grok 的 /always-approve on 或 off 后会被记住，重启后不会变回原来的设置。
- Antigravity 的服务不存在时，设置里它的卡片会显示「未安装」并提供「安装」。安装失败后的说明只在用 npm 安装时才提到 npm。
- agent 还在启动时点停止，回复会立刻结束。
- 出错的回复不再提供「添加回应」。
- 排队的消息只在鼠标移上去时才显示操作按钮；排队栏的文字与输入框对齐，玻璃效果下排队栏也和输入框一样是磨砂的。
- 给对话起标题这类后台小任务，不再出现在 Codex 自己的会话列表里。agent 支持时，Ancora 会在用完后删除这个会话。
- 新讨论串的第一条提示里，不再带用不上的交接段落。
- 重启后，协调者只收到一份讨论串名单，状态用文字写出。
- 项目主对话里「需要您决定」那一行，在您做出选择后会变灰。
- 开讨论串时，协调者回的那一句话不再触发桌面通知。
- 连续两次快速换 agent 时，以后一次的选择为准。
- 模型菜单显示实际的模型：「Default (recommended)」这类代称，显示成它实际对应的模型；查不出是哪个模型时就不列出。
- Claude Code 的思考强度不再显示「每次询问」。那是它的 Default 档，被误当成权限模式来翻译。现在从「中」档开始，模型芯片上只显示模型名。
- 「常用文件夹」和「自动建的文件夹放在」合并成一个**默认文件夹**（设置 → 通用，默认是 文档/Ancora）。新项目在这里建自己的子文件夹；对话在 agent 做出文件时建。单个对话或项目仍可以另选文件夹。
- 对话不会再被放到主目录、磁盘根目录或 Ancora 的数据目录里。之前被放进这些目录的对话，会移回「对话」组。
- 开关玻璃效果时，消息气泡不会再错开一个像素。
- Grok 的诊断日志里不会再刷满「Got response to unknown request skills-reload」：那是 Grok 对它自己内部请求的回应，现在 Ancora 会忽略它们。
- 面板变窄时，项目右侧的「讨论串」标签不会再挤成竖排；「新建定时任务」挪到了定时任务列表的顶部。
- 讨论串第一轮的提示词和工具说明大约少了一半（从约 9600 字减到约 5200 字）。管项目的工具（看板、定时任务、记忆整理）只留给协调者；电脑控制的工具只在打开「电脑控制」时才提供。
- 选择文件夹的对话框会在对话当前的文件夹或默认文件夹里打开，不再停在桌面（Windows 读桌面可能很慢）。
- 名字以 Auto 开头、或带「(recommended)」的真实模型重新出现在列表里，标签会去掉。
- 升级后，旧的「常用文件夹」不再变成默认文件夹，而是留在最近用过的文件夹里。旧版本放在主目录里的项目，会去掉这个文件夹。
- agent 压缩上下文后不会再丢掉 Ancora 的规则。Claude Code 和 Grok 把规则当作系统提示词接收；其他 agent 压缩后，下一条消息开头会把规则重发一遍：agent 主动报告压缩时，回复里会显示「压缩上下文」这一步；不报告的（Qoder），看它报告的上下文是否突然减半来判断。
- 切换「玻璃效果」时不再闪一下：页面淡入淡出，窗口材质在淡出后才切换。
- Claude Code 菜单里的「Agent」选项现在叫「角色」，选项是「默认」和它自带的子 agent（比如 claude-code-guide）；之前误译成了「每次询问」。
- 旧版本把项目放在主目录时，项目主对话和讨论串里存的路径也一并清掉，协调者不会再在主目录里开会话。
- 选了 `/子对话` 但还没写内容时，发送按钮保持灰色。英文界面写作「Started just now」。
- 表情回应菜单改成一行紧凑的表情，不再是一长条列表；加上的回应显示成小胶囊。
- 已发送消息里的 / 命令改成强调色文字，不再是气泡里套一个标签；两条消息连着时，中间留出复制、编辑按钮的位置。
- agent 还在连接时，停止（或「立即发送」）也有效，原来那条消息不会再发出去。
- 您拒绝 agent 的请求后，agent 会知道原因（「用户没有允许…」），不再只收到「Internal error」。
- 回复被中断、或上方内容高度变化后，对话仍然跟着最新消息；只有您自己往上滚才会停下。
- 切换外观时，如果淡入淡出被下一次切换打断，不再在日志里报错。
- 菜单和按钮只给当前用得上的选项。已经选了文件夹时，文件夹菜单只围绕这个文件夹（打开、换一个、最近使用、不使用文件夹），不再推荐别的项目文件夹。「重试」只出现在最后一条回复上，回复进行中不显示；出错的回复只有一个重试，不再两个。「转为讨论串」只出现一次。没有文字的消息不显示复制和编辑。设置里只对已安装、未登录的后端显示「登录」，只对能用的后端显示「设为默认」。初次设置时，已登录的后端不再要求登录。还没开始对话时不显示「压缩上下文」。搜索项目时，侧栏不再列出已归档的项目，项目页不再出现「创建第一个项目」；搜索讨论串不再改变「都已解决」那一行。空的设置项不能保存。
- Antigravity 每次启动新的服务进程时会自己重新登录（用 Gemini API Key，或它保存的 Google 登录），并且通过它声明支持的位置把 Ancora 的规则放进系统提示词。
- 电脑控制不再按「能不能看图」挑后端：设置里那份后端列表去掉了，每个 agent 都拿到全部工具。模型看不到截图时，第一张截图里的说明会让它停下，告诉您换一个能看图片的模型。
- 「后台」只列出比回复活得久的工作：回复结束时还在运行的命令，以及 agent 自己的后台任务（Grok）。在回复里跑完的命令是那条回复的步骤，只留在回复里。点开命令可以看输出，运行中会实时跟着更新。
- `/rename 名字` 也会给 Ancora 里的对话改名。agent 命令没有回复时仍会说明已执行；只是以 / 开头、并不是 agent 命令的文字，不再出现这一行。
- 消息的复制、编辑按钮放在气泡旁边，不会再压到上一条消息。
- 菜单背后的列表重新排序时（比如正在回复的对话在侧栏里往上移），菜单跟着按钮走，不再错位。
- 用量弹窗里的「压缩上下文」英文改为 "Compact context"，Grok 自己的那一步改叫「自动压缩上下文」；折叠里的网页搜索算作「搜索了 N 次网页」，不再算成「用了 N 个工具」。
- 所有「正在…」状态（加载模型、压缩上下文、检查、读取输出）都有和回复步骤一样的流光，一看就知道在进行中。agent 启动较慢时，几秒后会说明「正在启动 Antigravity…（第一次可能要半分钟）」；模型菜单最多等 90 秒，之后显示「重试」，不再一直转圈。
- 定时任务直接选 agent（默认选好默认后端），不再有「默认」这一项；结果发到项目时不显示 agent 一栏，因为项目的主对话有自己的后端。
- agent 没有的 / 命令不再当成普通消息发给它（之前给 Antigravity 发「/compact」，它没有这个命令，模型把它当文字回答了）：现在 Ancora 会提示 agent 的命令里没有它，再按一次 Enter 就照原样发出（比如 /tmp 这样的路径，或者 agent 能用但没列出来的命令）。agent 自己没有 `/rename` 时，`/rename 名字` 由 Ancora 直接给对话改名。新对话页还没有对话可改，会提示先发一条消息，不会把命令发给 agent。
- 对话的计划卡：计划全部完成后，下一条消息时收起；对话换了 agent 时清掉（新 agent 没见过那个计划）；agent 把计划清空时，卡片也去掉。
- 用量统计会去掉已经没有的回复（删掉的对话、重新生成前的回复），不用重启。用量很少的模型显示「<1%」，不是「0%」。
- agent 启动超过 90 秒时，模型菜单写「X 还在启动 · 重试」，不再写「无法加载模型列表」。Grok 失败但没有退出码的任务显示「失败」，不再编一个退出码。Codex 没报总数时，新输入不再显示为 0。
- Antigravity 的残留进程每次打开 Ancora 只查一次，不再每次启动都查。
- 崩溃或强制退出后留下的 Antigravity 服务进程（它不会随 Ancora 一起退出），会在下次启动服务和重新安装前结束掉，不再占着文件。只结束父进程已经不在的那些。

- 审批一次只给一个，出现在提出它的对话或项目里：最早的那个留在屏幕上，下面写「还有 N 个等您确认」；答完后下一个原地接上，卡片不会跳动或闪一下。
- 回复结束后显示输出速度：每秒多少 token（tok/s），以及每个输出 token 用多少毫秒（TPOT），在回复的用量一行和用量弹窗里。没有速度时，弹窗会说明原因：agent 没报输出 token、回复太短测不准、中途等了您或工具、或者被停止了。流式输出时 ACP 不给 token 数，要显示实时速度只能估算，所以不显示。agent 自己的 / 命令不再计时，也不再算作「后端未提供用量」的回复。
- 发送队列里的「立即发送」改成图标按钮，和同一行的其他按钮一致。
- Qoder 运行的命令现在显示输出。Qoder 自己运行命令，却把它报成一个 Ancora 没开过的终端，所以那一步只显示「[terminal toolu_…]」；现在从它一起发来的输出里读取（其他这样报命令的 agent 也适用）。
- Qoder 的上下文圆环和自动压缩改从 Qoder 自己的会话日志读取（它不通过 ACP 报这两样），所以上下文数字是真的；Qoder 自己压缩之后，Ancora 的规则会重新发给它。Qoder 的 /compact 不能通过 ACP 运行，所以它没有压缩按钮。
- agent 运行时在 Ancora 之外登录（比如在自己的终端里运行 `qodercli login`），之后点「重试」就能用。只在启动时读取登录状态的 agent，说未登录且上面没有别的回复在跑时，会自动重启一次再试；输入框里的「未登录」也会更新。
- 回复因为 agent 的轮次上限、长度上限或拒绝回答而停下时，回复下面会写明原因，不会看起来像已经说完。
- 停在新对话页时删掉对话，页面上的小组件会跟着更新。
- 应用和测试里不再有个人路径或名字：Ancora.exe 的公司和版权写的是「Ancora contributors」（不再是 Electron 默认的「GitHub, Inc.」）。

## 还没在真机上验证

- Grok 会不会通过 ACP 报告用量。可以在 设置 → 关于 → 诊断 里查看。
- 登录后的 Qoder。真实的 qodercli 1.1.72 和 1.1.73 只跑到登录为止（检测安装、启动、「未登录」状态和登录提示）。登录之后的部分（模型、模式、思考强度、计划、命令、审批、用量、从日志读的上下文）是用一个按 qodercli 安装包里的真实消息格式回放的替身测的，没有用真实账号。在 Qoder 里换模型，也会改掉 Qoder 自己的默认模型。
- 真实的 agent 发来 ACP 计划时，计划卡显示得是否正常。
- 「后台」只列出 agent 通过 Ancora 的终端运行、回复结束时还在跑的命令，以及 Grok 的后台任务。Codex 和 Claude Code 用自己的 shell，它们的命令可能不会出现在这里。
- Codex、Qoder、Grok 改文件时会不会标出文件（ACP 的 locations 或 diff）。「改动」标记要靠这个。
- Grok 的权限模式要在登录后的 Grok 上验证；Antigravity 整个流程也还没跑过。构建机连不上 Google 的下载地址，而且据报告它的服务在 Windows 上启动要 15 到 25 秒。
