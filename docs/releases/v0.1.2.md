# Ancora 0.1.2

Resizable panes, a project menu with notification levels, @ to hand a message to a thread, threads that leave each other messages, a plan card at the top of each thread, and switching model or agent while a reply runs.

> **Unofficial.** Ancora is an independent open-source project, not affiliated with, endorsed by or sponsored by Anthropic, OpenAI, xAI or Qoder. "Claude" is a trademark of Anthropic.

**Download:** `Ancora-Setup-0.1.2.exe` (installer) or `Ancora-0.1.2-win.zip` (unzip anywhere and run `Ancora.exe`). The build is not code-signed, so if SmartScreen asks, choose **More info → Run anyway**. Releases are Windows only: macOS and Linux build from source with `build.sh` (see the README).

## What's new

- **Resizable sidebar and thread panel.** Drag the inner edge of either one (the pane follows the pointer), or focus it and use the arrow keys. Double-click or press Home for the default width. Ancora remembers the width you chose. When the window gets narrow, the sidebar keeps its width and the thread panel gives way. If even that leaves too little room, the panel opens over the conversation, and Esc or a click outside closes it.
- **Project menu like Claude's.** The 「…」 or right-click menu on a project has open with, pin (P), rename (R), notifications, settings (S), archive (A) and delete (D). There are four notification levels: every new message; the project chat and anything that needs you (the default); only what needs you; or nothing. "Needs you" means a decision, a permission request or a stuck thread.
- **@ a thread from the project chat.** Type @ (also after Chinese text, as in 「请@整理」) and pick a thread. The message goes straight to that thread, and the project chat keeps a single 「已转给 …」 line.
- **Threads can leave each other messages.** A thread can hand another its results with a note, sent now, when the other is free, or after its current task. The sender sees where the message went and whether it arrived, and can cancel it while it waits. The receiver sees who it is from and what came with it. The board shows when a message is waiting.
- **A plan card at the top of each thread.** It stays put and updates in place. Done steps have a filled check, the running step a spinner with its time, waiting rows a ⊙, and steps not yet started a dashed circle. It opens when a turn starts and folds to one line when everything is done. When the agent sends its own ACP plan, the card shows that. Waiting on your decision, or on another thread, is added by the app. Steps that only narrate the interface ("reply to the user", "send a card") are left out.
- **Quieter threads.** Each thread is one well-defined task. It works without chatting and speaks only with a result, a blocker or a decision for you. Progress goes on the plan card. The coordinator learns of finished threads from one up-to-date list, without a note in the chat.
- **Switch model or agent while a reply runs.** The menus stay open. Another model, mode or thinking level applies from the next turn, and the reply keeps going. Another agent takes over with your next message, so the reply isn't cut while you choose; if it is still running when you send, it stops then, what it said stays (marked 「已中断：换成了 …」), and the new agent is told where it stopped. Picking the first agent again cancels the switch.
- **Threads open full screen as in Claude.** The full-screen button lays the thread over the project chat, with mark-as-resolved and close in its header; Esc returns.
- **Files beside a chat, and the project Library.** The folder button in a chat's header opens a pane with the working folder as a tree (with a filter), the opened file on the right (Markdown rendered, code and text as is, images shown), and the files the agent changed marked with a dot or listed under 「改动」. In a project, the same view is the 库 tab next to 讨论串; the other views (outputs, project files, memory, routines, milestones) moved under 「…」.
- **Background.** The same pane lists the chat's sub-chats and the commands the agent runs through Ancora, with a stop button for each running command. The folder button shows a dot while something runs.
- **/ commands.** Type / in the composer for a menu as wide as the composer: Ancora's own commands first, then the agent's (such as /compact), each with an icon for its kind and its description. /子对话 hands the rest of the line to a new sub-chat (in a chat), /讨论串 starts a thread (in a project). A picked command becomes a chip in the composer (Backspace or × removes it), and it stays highlighted in the sent message.
- **A sub-chat starts with the background.** It gets the main chat's latest lines and can read more of the main chat itself when it needs to.
- **Sub-chats delete on their own.** Deleting a sub-chat removes its card from the main chat; deleting the main chat keeps its sub-chats as chats of their own.
- **A folder in one click.** A chat or project without a folder offers 「在默认文件夹里新建」 and 「选择文件夹…」 in its files pane. Without a choice, a chat still gets its folder once the agent makes files.
- **A chat keeps track of its sub-chats.** Before its next turn the main chat's agent gets one up-to-date list of its sub-chats (state, current step, latest result), only when something changed, and can look them up any time. It still can't steer them.
- **Compact on request.** When the agent offers its own compact command (Claude Code's /compact), the context ring's menu has 「压缩上下文」.
- **Retry keeps the session.** Retrying or editing your last message continues the agent's session (and its cache) instead of replaying the whole conversation.
- **Long replies stream smoothly.** Only the part being written is re-rendered.

## Fixes

- A thread's first prompt no longer carries a hand-over section it doesn't need.
- After a restart, the coordinator gets the thread list once, with states in words.
- A 「需要您决定」 line in the project chat greys out once you've chosen.
- Starting a thread no longer raises a desktop notification for the coordinator's one-line reply.
- If you switch agents twice in quick succession, the later choice is the one that sticks.
- The model menu names the real model: a stand-in like "Default (recommended)" shows as the model it stands for, or is left out when no one can tell which model that is.
- Claude Code's thinking level no longer reads 「每次询问」. That was its "Default" level, mistranslated as a permission mode. The level now starts at Medium, and the model chip shows only the model name.
- One **default folder** (Settings → General, 文档/Ancora unless you change it) replaces 「常用文件夹」 and 「自动建的文件夹放在」. A new project gets its own subfolder there; a chat gets one once the agent makes files. Any chat or project can still use a folder you pick.
- A chat is never filed under your home folder, a drive root or Ancora's own data folder. Chats an earlier version put there move back to the plain chats.
- Switching 玻璃效果 on or off no longer shifts message bubbles by a pixel.
- Grok's diagnostics log no longer fills with 「Got response to unknown request skills-reload」: those were Grok's answers to its own internal requests, which Ancora now ignores.
- The project panel's tabs no longer squeeze into a vertical 「讨论串」 when the panel is narrow, and 「新建定时任务」 sits at the top of the routines list.
- Threads start with about a third less prompt. Tools for running the project (the board, routines, memory upkeep) stay with the coordinator.
- An agent no longer loses Ancora's notes when it compacts its context. Claude Code and Grok get them as part of their system prompt; other agents get them again at the top of the next message after a compaction, whether the agent announces it (shown as a 「压缩上下文」 step) or its reported context suddenly halves (Qoder).

## Not yet tested on a real machine

- Whether Grok and Qoder report usage over ACP: Settings → About → Diagnostics shows it.
- How the plan card looks when a real agent sends an ACP plan.
- The 后台 list only shows commands an agent runs through Ancora's terminal. Codex and Claude Code run their own shells, so their commands may not appear there.
- Whether Codex, Qoder and Grok mark the files they change (ACP locations or diffs), which the 「改动」 marks rely on.

# Ancora 0.1.2

侧栏和讨论串面板可以拖动调宽。项目菜单新增了通知分档。在主对话里可以用 @ 把消息直接交给讨论串。讨论串之间可以互相留言。每个讨论串的顶部有一张计划卡。回复进行中也能换模型或 agent。

> **非官方项目。** Ancora 是独立的开源项目，与 Anthropic、OpenAI、xAI、Qoder 均无关联，也没有得到它们的认可或赞助。「Claude」是 Anthropic 的商标。

**下载：** 安装包 `Ancora-Setup-0.1.2.exe`，或免安装的 `Ancora-0.1.2-win.zip`（解压到任意位置，运行 `Ancora.exe`）。程序没有代码签名，如果 SmartScreen 拦截，点「更多信息 → 仍要运行」。发布页只提供 Windows 版本，macOS 和 Linux 请用 `build.sh` 从源码编译（见 README）。

## 新功能

- **侧栏和讨论串面板可以调宽。**
  - 拖动面板的内侧边缘就能调宽度，宽度随鼠标实时变化；也可以选中边缘后用方向键调。
  - 双击边缘或按 Home，恢复默认宽度。
  - 调好的宽度会被记住。
  - 窗口变窄时，侧栏保持您设的宽度，讨论串面板先变窄。再窄的话，面板会改成浮在对话上方，按 Esc 或点面板外面就能关掉。
- **项目菜单和 Claude 一样。**
  - 在项目上点「…」或右键，菜单里有：打开方式、置顶 P、重命名 R、通知、设置 S、归档 A、删除 D。
  - 通知分四档：所有新消息；协调者与 @提及（默认）；仅 @提及；无。
  - 「@提及」指需要您本人处理的事，包括要您做决定、请求权限，以及讨论串卡住了。
- **在主对话里 @ 讨论串。** 打 @ 后选一个讨论串，消息会直接发给它，主对话里只留一行「已转给 …」。中文写法「请@整理」也能弹出列表。
- **讨论串之间可以留言。**
  - 一个讨论串可以把成果连同留言交给另一个讨论串。送达时机有三种：马上送、等对方空闲时送、等对方做完手头的事再送。
  - 发出方能看到留言发给了谁、送到没有，还没送到时可以取消。
  - 收到方能看到留言来自哪个讨论串，以及附带的产物。
  - 看板上会显示哪个讨论串有留言在等着送。
- **讨论串顶部有计划卡。**
  - 卡片固定在顶部，原地更新。
  - 已完成的步骤是实心勾，进行中的步骤转圈并显示用时，等待中的是 ⊙，还没开始的是虚线圈。
  - 新一轮开始时卡片自动展开，全部做完后收成一行。
  - 后端发了自己的 ACP 计划时，卡片就显示它。「等您决定」「等另一个讨论串」这类行由应用自动加上。「回复用户」「发卡片」这种只是复述界面动作的步骤会被去掉。
- **讨论串更安静。**
  - 每个讨论串只负责一件定义明确的事，安静地做。只在有结果、卡住了或需要您决定时才说话，进度都写在计划卡上。
  - 协调者从一份最新的讨论串名单里得知哪些做完了，主对话里不会多一条通知。
- **回复进行中也能换模型或 agent。**
  - 回复进行中，菜单也能打开。
  - 换模型、模式或思考档位，从下一轮开始生效，当前回复不会中断。
  - 换 agent 也不会马上打断：选好后，从您发下一条消息起才正式换。如果那时回复还没说完，才会停下，已经说的内容保留，并标上「已中断：换成了 …」，新的 agent 会知道上一轮停在哪里。发送前再选回原来的 agent，就等于取消。
- **讨论串可以像 Claude 一样全屏。** 点全屏后，讨论串铺满项目主对话的位置，顶部有「标记为已解决」和「关闭」，按 Esc 退出。
- **对话旁边能看文件，项目有了「库」。**
  - 对话标题栏右边的文件夹按钮会打开一个面板：左边是工作文件夹的目录树，可以筛选；右边预览打开的文件（Markdown 会渲染，代码和文本原样显示，图片直接显示）。
  - agent 改过的文件带一个圆点，也可以点「改动」只看这些文件。
  - 项目右侧的「库」标签是同一个视图，和「讨论串」并列。其他视图（成果、项目资料、项目记忆、定时任务、里程碑）收进了「…」菜单。
- **后台。** 同一个面板里列出这个对话的子对话，以及 agent 通过 Ancora 运行的命令。正在运行的命令可以点停止。有东西在运行时，文件夹按钮上会有一个圆点。
- **/ 命令。** 在输入框里打 /：对话里用「/子对话」把这行后面的内容交给一个新的子对话；项目里用「/讨论串」开一个讨论串；agent 自带的命令（例如 /compact）列在后面。
- **/ 命令菜单。**
  - 在输入框里打 /，弹出和输入框一样宽的菜单：先列 Ancora 自己的命令，再列 agent 自带的命令（例如 /compact）。每条有表示类别的图标和说明。
  - 选中的命令会变成输入框里的一个标签，按退格或点 × 可以去掉；发出去的消息里，这个命令也会高亮显示。
- **子对话带着背景开始。** 用 / 开子对话时，子对话会拿到主对话最近的内容，需要更多时可以自己去读主对话。
- **子对话可以单独删除。** 删掉子对话，主对话里它的卡片也会去掉；删掉主对话，它的子对话会保留，变成独立的对话。
- **一键给对话配文件夹。** 没有文件夹的对话或项目，在文件面板里可以点「在默认文件夹里新建」或「选择文件夹…」。不选也没关系：agent 做出文件时会自动建好。
- **主对话能掌握子对话的进展。** 主对话的 agent 在下一轮开始前，会收到一份最新的子对话名单（状态、当前步骤、最新结果），只在有变化时才给，也可以随时查看。它仍然不能指挥子对话。
- **手动压缩上下文。** agent 自带压缩命令时（例如 Claude Code 的 /compact），点上下文圆环，菜单里有「压缩上下文」。
- **重试沿用原来的会话。** 重试或编辑最后一条消息时，沿用 agent 原来的会话和缓存，不再把整段对话重放一遍。
- **长回复显示更流畅。** 流式输出时只重新渲染正在写的那一段。

## 修复

- 新讨论串的第一条提示里，不再带用不上的交接段落。
- 重启后，协调者只收到一份讨论串名单，状态用文字写出。
- 项目主对话里「需要您决定」那一行，在您做出选择后会变灰。
- 开讨论串时，协调者回的那一句话不再触发桌面通知。
- 连续两次快速换 agent 时，以后一次的选择为准。
- 模型菜单显示实际的模型：「Default (recommended)」这类代称，显示成它实际对应的模型；查不出是哪个模型时就不列出。
- Claude Code 的思考强度不再显示「每次询问」。那是它的 Default 档，被误当成权限模式来翻译。现在从「中」档开始，模型芯片上只显示模型名。
- 「常用文件夹」和「自动建的文件夹放在」合并成一个**默认文件夹**（设置 → 通用，默认是 文档/Ancora）。新项目在这里建自己的子文件夹；对话在 agent 做出文件时建。单个对话或项目仍可以另选文件夹。
- 对话不会再被放到主目录、磁盘根目录或 Ancora 的数据目录里。之前被放进这些目录的对话，会移回「对话」组。
- 开关玻璃效果时，消息气泡不会再错开一个像素。
- Grok 的诊断日志里不会再刷满「Got response to unknown request skills-reload」：那是 Grok 对它自己内部请求的回应，现在 Ancora 会忽略它们。
- 面板变窄时，项目右侧的「讨论串」标签不会再挤成竖排；「新建定时任务」挪到了定时任务列表的顶部。
- 讨论串开头的提示词少了约三分之一。管项目的工具（看板、定时任务、记忆整理）只留给协调者。
- agent 压缩上下文后不会再丢掉 Ancora 的规则。Claude Code 和 Grok 把规则当作系统提示词接收；其他 agent 压缩后，下一条消息开头会把规则重发一遍：agent 主动报告压缩时，回复里会显示「压缩上下文」这一步；不报告的（Qoder），看它报告的上下文是否突然减半来判断。

## 还没在真机上验证

- Grok 和 Qoder 会不会通过 ACP 报告用量。可以在 设置 → 关于 → 诊断 里查看。
- 真实的 agent 发来 ACP 计划时，计划卡显示得是否正常。
- 「后台」只列出 agent 通过 Ancora 的终端运行的命令。Codex 和 Claude Code 用自己的 shell，它们的命令可能不会出现在这里。
- Codex、Qoder、Grok 改文件时会不会标出文件（ACP 的 locations 或 diff）。「改动」标记要靠这个。
